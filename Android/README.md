# Android development port

**The installed generic UI prototype was rejected as an experience port.** Follow `Docs/Product/PRODUCT-REQUIREMENTS.zh-CN.md` and the phased plan. Do not ship or install that UI as an iOS-parity candidate; rendering research and native core tests do not establish product acceptance.

This is a native Kotlin / C++ port, not an iOS wrapper. It is not yet feature
complete or approved for release. Phone browsing exposes GBA, GBC and PSP;
tablet browsing exposes five families, with unverified 3DS gameplay explicitly
blocked. ARM64 development packs now include source-built PPSSPP and melonDS DS;
commercial compatibility is still scenario-specific. See the latest [runtime/tablet evidence](../Docs/Product/ANDROID-RUNTIME-AND-TABLET-2026-10-28.zh-CN.md).

## Build

Install JDK 21, Gradle 8.13, SDK platform/build-tools 36, NDK 27.2.12479018 and
CMake 3.22.1. Set ANDROID_HOME and JAVA_HOME. Keep SDK paths in local.properties
(ignored), never in tracked files.

```sh
# From Android/. Both private inputs are optional and DEBUG-only.
export UNCLEED_PRIVATE_ASSETS=/absolute/path/to/private/assets
export UNCLEED_PRIVATE_CORES=/absolute/path/to/private/jniLibs
export UNCLEED_PRIVATE_RESOURCES=/absolute/path/to/private/android-res
gradle :app:testDebugUnitTest :app:assembleDebug
```

Generate the private launcher/splash resources with `Scripts/prepare-android-private-resources.py` using the existing Apple Assets directory. A missing original icon must fail instead of silently shipping the Android robot. Public release resources remain pending.

The asset pack contains `models/{gba,gbc,nds,psp,3ds}-{0,1,2,3}.glb` and
`models/media-{family}.glb`, converted directly from the shared Apple geometry.
Do not commit this pack. `Scripts/export-android-gltf.swift` preserves node
hierarchy, materials and physical controls. The debug core pack uses Android
ABI subdirectories, e.g. `arm64-v8a/libmgba_libretro.so`.

Release source sets intentionally do not inherit these private input directories.
Do not distribute a debug APK as a signed release. Public model resources,
upstream corresponding sources and stable signing are still release prerequisites.

## Private closed-test beta

The `beta` build type is non-debuggable, uses application ID `org.uncleed.app.beta`
and a persistent, separately backed-up signing key. It deliberately coexists with
the developer app; their libraries/saves are separate. It is not public asset
clearance. At the owner's request, the private Release includes current appearance
inputs as a separate archive, without ROMs or personal data.

Set the three private input variables above, `UNCLEED_BETA_KEYSTORE` to your local
PKCS12 keystore, and `UNCLEED_BETA_STORE_PASSWORD` to its password. The alias is
`uncleed-beta`; keep credentials out of source and command logs. Then build:

```sh
gradle -PuncleedVersionName=0.1.0 -PuncleedAbis=arm64-v8a :app:assembleBeta
```

Use your own signing key to rebuild; only the maintainer's same key can update
an already-installed official beta without reinstalling. The adjacent Release
contains exact core source archives and `rebuild-beta-cores.py` (Python >= 3.12).
See [installation, limitations and Apple distribution status](../Docs/Releases/v0.1.0-beta.1.zh-CN.md).

## Validation still required

- Physical OPPO Find X6 rendering, multitouch, controllers and lifecycle.
- Tablet portrait / landscape / multiwindow safe-area and dual-screen input.
- Exact visual parity including frost, labels, game covers and spotlight.
- Continuous selection transitions, loading mechanics and mechanical audio.
- PSP / NDS core integration, sustained gameplay/audio, save/relaunch checks.
- Import metadata/cover lookup parity and hostile ZIP tests on device.

Current browsing and core smoke tests are development evidence only. Never infer
commercial-game compatibility from a synthetic probe.

## Selected-model rim and frame synchronization

The private `rims/{family}-{theme}` pack is generated by
`Scripts/AndroidRimExport.swift` from the same solid model and iOS rim renderer.
It records 16 idle poses, fixed projected bounds and the exact GLB content hash.
The app loads alpha masks off the main thread within a 32 MiB bound; it never
uses a white rectangle as a placeholder or performs GPU snapshots while browsing.
A mismatched model hash, filled mask or incompatible scale hides the effect.

`ShowcaseRenderer` stamps actual rendered buffers with their presentation time.
The rim follows the corresponding `SurfaceTexture` update, not CPU ticks. This
matters when a slow GPU skips frames: a state update is not proof of a displayed
pose. No normal-frame GPU wait is added. Resize/teardown synchronization follows
the graphics API lifecycle.

The UI instrumentation probe is separate from the synthetic core probe:
`am instrument -w -e probe showcase org.uncleed.app.test/org.uncleed.app.CoreProbeInstrumentation`.
It captures real page transitions and hold/move/release input without using ROMs.
Its state assertions must still be followed by visual inspection of the screenshots.

## Hardware frame publication

The GLES3 host supplies an explicit color/depth-stencil framebuffer, restores readback state, and publishes an opaque LCD. GPU completion and software conversion happen outside the UI frame mutex; a short locked buffer swap publishes complete pixels and dimensions. Unchanged video serials skip duplicate texture uploads. Core cadence, presented UI frames, audio underruns and pause/focus metrics are separate diagnostics; none alone establishes game compatibility.

LCD frames use a separate ungraded display-RGB pass and nearest sampling; shell PBR lighting remains unchanged. Captions follow presented media frames. Physical game controls and PSP utility caps support eased press travel and system-respecting haptic detents. See `../Docs/Product/ANDROID-COLOR-SHELF-HAPTICS-2026-10-28.zh-CN.md` for measured scope and remaining work.

NDS alone exposes book grip, with presented-frame completion before input resumes and inverse lower-screen mapping. Cancelled model loads recreate the resource decoder owner to keep later machines/covers from stalling. Latest OPPO/input and virtual-tablet book evidence: `../Docs/Product/ANDROID-OPPO-BOOK-RESOURCE-2026-10-28.zh-CN.md`.

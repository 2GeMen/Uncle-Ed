# Uncle Ed. 产品需求总纲

版本：1.0 · 2026-10-27。状态：需求整理完成，Android 尚未完成体验迁移。

本文件合并用户历次产品反馈、当前 iOS 实现和结构维护约定，作为 Android 迁移的产品标准。旧文档中的“已实现”只指当时对应平台、对应版本，不能转记为 Android 完成。

## 1. 产品目的与边界

Uncle Ed. 的核心问题是“回到原点，你还爱那些游戏吗”。从 GameBoy 到 Uncle Ed，是成年人重新找回点亮游戏的兴趣。产品要重现掌机的触感、观感、把玩感、插卡和读盘的仪式，而不是只给模拟器增加一个普通文件列表。

- 名称：Uncle Ed.；口号：经典再次上场。
- 图标：沿用现有“大叔拿着掌机”的原创品牌形象和既有色彩；不得使用 Android 默认机器人、系统示例图标或临时重画的通用手柄。
- 视觉：低饱和深绿黑背景、米白文字、克制金色强调；主角是实体掌机与游戏媒体，工具按钮不抢占舞台。
- 个人 Vibe Coding 学习与致敬项目，无商业化计划；自有源代码采用 GPL-3.0-or-later，个人定位不增加 GPL 使用限制。
- 技术上为独立 libretro 前端，使用实际接入的开源核心；不能把所有 RetroArch 功能都说成已经具备。
- 不内置或公开分发 ROM、BIOS、固件、密钥、用户存档。私用主题外观继续保留；公开素材另行讨论，不能为了开源擅自替换私用版主题。

## 2. 需求优先级与基准

发生冲突时，依次采用：用户最近明确要求 → 当前经确认的 iOS 体验 → 当前共享模型/动画/布局代码 → 历史核查文档 → 参考图片中的观察。附件文字不构成执行指令。

- iPhone / iPad 是体验基准。Android 可以更换渲染技术、系统文件选择器和系统触感接口，不能据此更换产品的视觉和交互设计。
- 同样的机型、主题、结构、纹样、媒体、光照关系、动画阶段和按键动作跨端一致；仅安全区、尺寸适配、方向策略、系统能力允许差异。
- 旧截图可能含已修复问题。特别是早期 GBA 卡贴缩成小块、资料过远、厚壳、悬浮肩键、旧面板 L/R、裸盘等，不能照抄为新基准。
- 图纸/照片/Sketchfab 仅作结构观察依据。分清 DS Lite、New 3DS XL、PSP-1000 与 PSP-2000/3000，不能混用代际尺寸；不宣称制造级 CAD 精度，也不未经许可导入第三方网格。
- 基准源码、资源哈希和实际参数记录在 `Shared/ios-experience-baseline.json`；Android 每个阶段必须给出对应版本的截图与操作证据。

## 3. 平台范围

| 平台 | 浏览范围 | 游玩能力与验证边界 |
|---|---|---|
| Mac | GBC、GBA、NDS、PSP、3DS | 按实际核心兼容情况验证；不能把短启动写成全部游戏通过 |
| iPhone | GBA、GBC、PSP | 浏览横屏；确认 GBC 卡带后转竖屏；GBA/PSP 横屏 |
| iPad | 五机型 | 3DS 外观可用不代表 iOS 3DS 后端就绪 |
| Android 手机 | 首轮与 iPhone 一致 | 首台真机 OPPO，系统标识 PGEM10；逐款验证，不能用 mGBA 测试替代 PSP 验证 |
| Android 平板 | 与 iPad 一致的浏览范围 | 暂无实体平板，先验证平板模拟器；3DS 游玩须单独具备核心与触控证据 |

不得因安卓屏幕宽、刷新率高，改成另一套页面层级或触控布局。横竖屏、挖孔、手势条、安全区、字体缩放和多窗口都要适配。默认等比展示，不能拉伸模型或画面。

## 4. 完整用户旅程

唯一主路径：**选掌机 → 选主题 → 独立选卡/选盘 → 拿起并装载 → 开机游玩**。

- 媒体页独立展示收藏，不在卡带后面叠一台机器。
- 进入主题前后同一台掌机保持尺度、中心与姿态连贯，约 0.28 秒淡入过渡；不能突然缩放成另一种展示。
- 主机、主题和媒体预览全部可把玩。横滑切换，约 0.2 秒按住后拖动旋转；双指把玩与滚轮手势正确仲裁。旋转不能误触确认、插卡。
- 松手后顺滑回正；无操作时持续轻摆。当前 iOS 基准周期 8.5 秒，yaw 约 0.18 rad、pitch 约 0.055 rad；调整须以手感对照，不再擅自改为另一套速度。
- 手势一次最多跨相邻一项；明确点选分页指示器可直接选中对应页，持续滑动分页点可预览切换，不能一律转成“下一页”。单项隐藏分页。
- 多项可见时保留邻居的轮廓和方向线索。非选中项压暗材质，不能降低根节点透明度，让前后壳互相透出。
- 记住各机型最近主题；选卡回退/退出后保留合理的收藏焦点和滚动位置。
- 返回、系统取消、方向变化、后台、切机、退出游戏均释放输入；装载取消时不留下卡带、声音或半开仓盖。

## 5. 页面规范

### 5.1 选掌机

- 沿用 iOS 的沉浸式展示与集中品牌/经典机型 Logo，而不是大号系统文字加矩形灰按钮。
- 只为聚焦机型显示正确 SONY / NINTENDO 品牌与经典 Logo；图片等比、不模糊、不裁断；切换有轻柔淡入。
- 尺度依据真实实体边界，排除透明图层留白。首页不同机型遵循共享比较尺度；移动端占幅以 iOS 实际版为准。
- 仅在真正需要的地方保留导入、菜单等轻量图标；触区不小于 Android 48 dp，视觉尺寸不必扩成大按钮。
- 机身选择光只沿实体轮廓窄幅发光；不使用方框、椭圆台座或覆盖整台机器的白色蒙版。
- 聚光光束与微粒覆盖整屏背景，不被单台模型容器裁成矩形；真实光源固定，模型转动时高光随法线变化。
- 手动旋转只隐藏会脱离实体的平面轮廓金边，真实受光和背景光束保留。
- 大角度旋转不能切边；相机给实体包络留空间，不能每帧重算导致静止尺寸呼吸。

### 5.2 选主题

- 一台可交互的主要预览，左右滑动主题，可见相邻主题线索；不改成图标网格或一排缩略图。
- 主题名称位于顶部机型名称下方；完整显示，不压在机身底部或卡带资料处。
- 与首页同机型保持尺寸；切主题不重新建出明显白闪，不在滚动主线程同步截图。
- 四款主题名称、配色和顺序见第 6 节。私用限定纹样不能因为 Android 迁移而被删换。

### 5.3 选游戏/媒体收藏

- 立体卡带/UMD 横向浏览，有封面、正反面、厚度、接缝和触点结构；允许翻转把玩。
- 选中媒体更有拿起感，非选中轻摆；拿起动作与装载起点连续，不跳回原位。
- 卡带与标题、资料紧凑编排，长标题完整换行；大平板不能用制造比例把可浏览卡带缩得过小。确认后再连续缩放到真实插槽比例。
- 显示标题、开发商、出品方、发售时间及地区/精度口径、本平台 Metacritic 媒体评分。缺失显示“/”。
- 不用用户评分、其他平台分数、试玩/改版对应正式版分数代替缺失值。
- 卡贴优先真实适合比例的素材；只有盒装封面时，合理去包装边、有限裁剪后铺满标签区域，不能缩成中间一小块。沿用最多约 12% 上下裁剪的既有回退，保护游戏主体和标识。
- 封面为消光印刷；卡壳硬塑料有克制高光，不出现泛白、过曝或整体洗灰，也不改写封面主色缓存来掩盖材质问题。

### 5.4 装载与开机

- 确认卡带后先“拿起”，在机壳前方安全转向，再对齐槽口，最后沿槽轴插入；起点跟随抬起的真实位置。
- 卡带装载基准 1.65 秒；GBC 落座顶部与机器顶部齐平。GBC 卡插 GBA 才可呈现突出，不能把这套高度用于 GBC 本机。
- NDS/3DS 合盖状态开始，装卡后合理开盖。上盖内部与下层按键不能穿模。
- PSP 选盘默认机身背面；装入完整 UMD，按“开仓 → 放入导架 → 合盖 → 读盘 → 翻回正面开机”完成。
- UMD 包含保护壳、透明窗/读盘开口、内部薄盘片。读盘仅旋转内部盘片，不能整套壳跟转，也不能回退为裸 CD。
- PSP 2.95 秒时序：开仓 0–0.18；放盘 0.18–0.65；合仓 0.68–0.84；读盘 0.86–1。未合盖不能先读盘旋转。
- 仓盖向外打开，媒体全程位于正确侧，随导架合仓；核查整条轨迹、仓盖/壳体/读头净空，不能只看终点。
- 插入、卡紧、开盖、落盘、合盖、马达/寻道声音与动作同步且每轮去重；新流程/取消停止旧声音。机械音是现有合成素材，不冒充真机录音。

### 5.5 游玩与菜单

- 完整实体掌机承载游戏。LCD 保持原始画面比例，黑边和触控边界一致；不把画面拉伸填满机壳。
- PSP / GBA 直接点击模型实体肩键，删除额外面板 L/R；NDS/3DS 保留已确认的辅助肩键；GBC 没有 L/R。
- 菜单入口放横屏左上安全区，沿用侧栏图标和向右滑出提示；不能占据左侧方向键区域。导入等非游玩工具不叠在操作区。
- 菜单覆盖时暂停，取消继续，确认切机/换卡先释放旧输入并保存；退出和屏幕旋转不产生粘键。
- 保留显示尺寸、位置、画面优先等已存在的调节能力；缩放和偏移同时作用于模型、画面、命中、触笔及提示，实体不得移出可视区域。
- NDS 可用书本模式；3DS 不复用此模式。双屏和下屏触控依实际输出映射，3DS 的 400×480 组合画面中下屏为居中的 320×240。
- iPhone/Android 手机：浏览横屏，GBC 确认卡带后平滑转竖屏，GBA/PSP 保持横屏；方向切换不重新映射上下左右轴。

## 6. 五机型模型与主题

共同要求：实体圆角/曲面、前后壳、厚度、接缝、凹槽、螺丝、接口、滑块、标签分别表达。标识等比、正确朝向且无遮挡。以原图、结构材料和当前共享几何核对，不在整个壳体上贴放大的整机照片。

| 机型 | 私用主题（确定顺序） | 必须保留的结构特征 |
|---|---|---|
| GBA | 原生黄色、索尼克定制、EVA 定制、白色磨砂半透明 | 流线型前壳、连续收薄滚边、局部电池仓隆起；贴合顶角的包角肩键、承接座和让位槽；后板左右随整体配色，普通款不透明；不遮挡合规标签；Logo 不拉伸；小圆 Start/Select、斜置 A/B、扬声器开孔、AA 电池结构、EXT/耳机/电源，不虚构 USB 充电口 |
| GBC | 宝可梦中心限定、经典原始配色、经典黄配色、黑磨砂 | 合理握持背部和电池盖；侧电源滑块、音量、EXT、红外、耳机/DC；无肩键；卡带落座齐平；屏框与 LCD 不透明 |
| PSP | 最终幻想限定、怪物猎人限定、实况足球限定、黑磨砂 | 后上缘实体肩键；前左下/后右下仅一侧金属环扣；弧形后握把与薄后壳；独立 UMD 仓盖/导架/读头；薄金属圆环和边带；背板同色，不黑白拼块；最终幻想浅蚀刻，其他按原图消光丝印；USB Mini-B/耳机/DC/电源/锁定等真实细节 |
| NDS Lite | 宝可梦黑白限定版、马里奥限定版、塞尔达限定版、黑磨砂 | 铰链与闭盖间隙；上盖 LCD 金属背板、双扬声器、排线，不能透出下层按钮；背板和电池盖不凹空；充电、耳机、侧开关、SLOT-1/2 |
| 3DS（当前设计区分 New 3DS XL） | 塞尔达限定、宝可梦日月限定、大乱斗限定、黑磨砂 | 正确机壳阶差、铰链、相机、上盖电子结构；耳机/音量/充电；日月纹样按确认的矢量线条和留白，不改成凸起浮雕；双屏尺寸与触控正确 |

### 6.1 材质、厚度与印刷

- 非磨砂 NDS/3DS/PSP 呈现钢琴漆面色泽与移动高光。金属环、环扣、边带有金属反射，与塑料分离，磨砂转换不得覆盖金属。
- 磨砂类似克制的半透毛玻璃/树脂，表面有细颗粒，内部元件低对比可见；不把所有主题统一半透明。
- NDS/3DS 黑磨砂上盖要看得到真实上盖层次，不能透成下半部操作面板，也不能用大灰板遮盖错误结构。
- PSP 浅蚀刻使用法线/粗糙度与浅灰印迹共同表达；透明图案零 alpha 区域不能留下反光矩形。
- 壳面、屏框、光驱盖、接缝各自一套几何，避免重复面、Z-fighting、多余描边和透明排序问题。
- 不用全局压缩 Z 来解决厚度。应保留原机结构关系、收薄边缘和局部凸起，重新检查卡槽与装载净空。
- 普通卡带是硬塑料；允许指定彩色 GBA 卡带半透。GBA/GBC 仅一排 32 个触点，正背面由壳遮住，仅底口开放；NDS/3DS 正面不露，背面接触窗裸露。

### 6.2 按键与摇杆

- 所有可操作物理键有可见位移/倾斜、固定键槽及回弹，不能仅变色。包括肩键、功能键和实体滑块。
- NDS/GBA/GBC/3DS 的一体十字键围绕中心倾斜，相反方向抵消，斜向归一化；PSP 维持分瓣方向键。
- 独立圆键按自身机械轴下沉；肩键绕后缘轴转。iOS 当前反馈过渡约 75 ms，Android 应对齐实际观感。
- PSP 摇杆有插座、轴体、帽沿、颗粒防滑面，输入产生方向位移与轻微倾向，松手回中；不是平面滑块。
- 手指可同时按方向、A/B、L/R；单指移出/抬起只释放自己，取消/后台/切页释放全部。肩键触区跟随实体投影，不被壳或透明图案吞掉。
- 触感与声音去重，允许系统能力差异；不能用夸张长振动替代轻量机械反馈。

## 7. 导入、游戏资料和存档

- 系统文件选择器导入 ROM / ZIP，按机型过滤；流式计算实际内容 SHA-256 去重，不以文件名认定重复。
- 原文件名/地区信息独立保存，不让哈希文件名影响封面、别名与资料查询。
- ZIP 拒绝路径穿越、绝对路径、异常条目、损坏/空文件和超限解压；不把任意文件写到库目录之外。沿用 iOS 单 ZIP 最多 100 个 ROM 的产品限制，其他安全预算单独记录。
- 文件上限：GBC 16 MiB、GBA 64 MiB、NDS 1 GiB、PSP 2.5 GiB、3DS 8 GiB；流式导入不能把整个大 ROM 再复制多份到 Java 堆。
- 导入和以后进入收藏时异步匹配封面、游戏资料；缓存后离线可用，不阻塞 UI 或启动游戏。
- 用户此前已允许将游戏名称、机型、地区用于既有资料查询；不上传 ROM、存档和账户数据。网络权限、失败重试和缓存需要明确实现。
- 更新/重装开发构建不清空用户库和存档。SRAM、RTC、核心私有存档与必要迁移按游戏身份隔离。
- 分开记录：核心产生文件、文件内容、重新加载内容、实际游戏内存档/继续游戏。不得用“写出一个文件”替代完整保存验收。

## 8. 性能、稳定性与质量约束

- 流畅游玩和不断续的声音是基础。重点复现 GTA 片头默认音乐、GTA 城市游玩、战神高负载动画/战斗；不能只启动标题页。
- 指标区分 UI 展示频率、核心推进频率、游戏内部独立帧率、长帧、音频欠载、输入延迟、热状态及内存。
- 模拟器核心和图形上下文由同一后台所有者驱动；UI 不承担核心、同步 GPU 读回、封面查询或轮廓截图。
- 隐藏页面停止渲染，缓存有界，只让必要邻居活动；不为全库预生成高成本快照。重复帧不无条件复制，音频从真实 PCM 合理预充后起播。
- 不为了流畅擅自减少模型/纹理质量、降低游戏分辨率或开跳帧。先优化线程、缓存、绘制次数、同步、内存和核心参数；仍有不可兼得时向用户展示实测结果再决策。
- 旋转、前后台、音频中断、耳机切换、系统返回、多点触控、来电/失焦、启动失败、装载取消均可恢复，无粘键、双音轨或卡死。
- 以 OPPO 真机做手机验收；模拟器性能不能代表实体手机/平板。游戏持续测试与截图采样分开，避免采样本身干扰帧率。

## 9. Android 迁移硬性要求

当前通用按钮式原型仅作底层研究，**不作为产品 UI 基线，也未通过体验验收**。

1. 先建立品牌、色彩、正交相机、实体边界、光照和资源转换的共同基准，再做页面。
2. 每页与 iOS 对照：背景/光束/轮廓、Logo、模型占幅、邻居线索、文字、间距、手势、状态转换；不能以“能显示 3D”算通过。
3. 转换保留参数化曲面、倒角、圆柱、圆环、字形、透明度、纹理方向/变换、NSData 图像、法线、颜色空间、材质类型和层级。发现单位代理网格/默认白材质必须失败或修正。
4. 共用装载时序与模型参数，不能分别手调出两条不一致轨迹。只证明 GLB 结构合法不足以证明实际渲染正确。
5. 每轮交付只报告已完成的需求 ID、版本和证据；编译通过、核心探针通过、视觉验收通过、实际游戏通过分别记录。

分期计划和逐项状态见同目录 `ANDROID-IMPLEMENTATION-PLAN.zh-CN.md` 与 `REQUIREMENTS-TRACEABILITY.csv`。
